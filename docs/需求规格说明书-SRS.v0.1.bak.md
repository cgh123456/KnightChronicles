## 1. 引言

### 1.1 编写目的

将 PRD 中的产品愿景与用户故事拆解为**可开发、可测试、可验收**的逐条需求，作为代码开发与测试用例设计的唯一基线。PRD 回答"做什么游戏、为什么做"，本文档回答"每一项功能具体做到什么程度才算完成"。

### 1.2 范围

覆盖 MVP v0.5 至 v1.0 的全部功能与非功能需求。v1.1+ 需求仅列出占位，不展开设计。

### 1.3 术语

| 术语 | 定义 |
| --- | --- |
| 单局 / Run | 从选角进入第 1 层到死亡或通关的完整过程 |
| 层 / Floor | 一个关卡主题内的一个地牢层，含 6–10 房间 + 层末出口 |
| 房间 / Room | 清怪开门的最小战斗/交互单元 |
| PCG | 程序化内容生成（Procedural Content Generation） |
| SO | Unity ScriptableObject 配置资产 |
| 无敌帧 | 翻滚等动作期间免疫伤害的时间窗口 |

## 2. 总体描述

### 2.1 产品功能结构

```
骑士异闻录
├── 核心战斗（移动/瞄准/射击/翻滚/技能/伤害/敌 AI/弹幕/Boss）
├── 角色系统（选择/属性/解锁）
├── 武器系统（配置/拾取切换/稀有度/分类）
├── 天赋系统（三选一/Buff 叠加）
├── 关卡与生成（PCG/房间流程/房间类型/层结构/种子/校验）
├── 掉落与经济（掉落表/双货币/商店）
├── 局外成长（宝石结算/解锁商店）
├── UI/HUD（大厅/HUD/结算/暂停/设置）
├── 存档（内容/原子写入/校验）
└── 音频（BGM/音效/混音分组）
```

### 2.2 运行环境与约束

- 操作系统：Windows 10/11 64 位；引擎 Unity 2022.3 LTS + URP；
- 输入：键鼠为主，手柄仅预留 Action Map（P2 实现）；
- 约束：纯单机、无网络通信、无第三方强制运行时依赖（见 PRD §2.3 Non-Goals）。

## 3. 功能需求（Functional Requirements）

### 3.1 核心战斗模块

| 编号 | 需求名称 | 优先级 | 需求描述 | 验收标准 |
| --- | --- | --- | --- | --- |
| FR-101 | 角色移动 | P0 | WASD 8 向移动，斜向速度归一化；启停响应曲线参数化（默认近似即时启停，惯性参数预留） | 对角线移动速度与直线速度偏差 ≤ 2%；按键到角色开始位移 ≤ 1 帧 |
| FR-102 | 鼠标瞄准 | P0 | 鼠标屏幕坐标经相机射线换算为世界瞄准点，准星 360° 跟随，角色朝向实时对准 | 准星与鼠标位置偏差 ≤ 1 个屏幕像素的等效世界距离；无坐标系漂移 |
| FR-103 | 射击 | P0 | 左键按住连发；伤害/攻速/弹速/散布/弹匣/能耗全部由武器配置驱动（FR-301） | 点击到子弹出膛 ≤ 100ms；射速误差 ≤ 5%（60 秒连发实测） |
| FR-104 | 翻滚 | P0 | Space 触发，方向 = 当前移动输入（无输入时为面向方向）；0.3s 无敌帧，CD 1.5s | 无敌帧内免疫一切伤害（自动化断言）；HUD 有冷却指示；翻滚不可被打断（霸体） |
| FR-105 | 角色技能 | P0（1 角色）→ P1（4 角色） | 各角色 1 个冷却型主动技能，右键/Q 释放；效果与数值走 SO 配置 | 技能效果与配置表数值一致（单测断言）；冷却 UI 实时准确 |
| FR-106 | 伤害计算 | P0 | 命中/暴击/减伤公式集中于逻辑层，表现层零计算；结算后广播事件 | 公式单元测试覆盖率 100%（含边界值）；伤害数字与公式结果完全一致 |
| FR-107 | 敌人 AI | P0 | 状态机或行为树：巡逻 → 索敌 → 攻击 → 受击 → 死亡；怪物行为参数走配置表 | 同屏活跃敌人 ≤ 25；AI 状态转换无死循环（1 小时压力测试无卡死） |
| FR-108 | 弹幕系统 | P0 | 对象池管理，同屏上限 500，超出回收最旧；三层碰撞矩阵（玩家弹/敌弹/地形） | 弹幕满载时帧率降幅 ≤ 5%；无一弹穿透错误层；敌方弹丸全部带自发光描边（可读性红线） |
| FR-109 | Boss 战 | P0（1 个）→ P1（5 个） | 脚本化阶段制（每 Boss ≥ 2 阶段，血量阈值切换）；大招必有落点/路径指示 | 阶段切换逻辑可配置；指示物先于伤害 ≥ 0.8s 出现；Boss 战性能不低于基线 95% |
| FR-110 | 垂直维度机制 | P1（是否进 MVP 待 PRD 评审确认） | 高台/立体掩体的高度差判定：低位掩体阻挡低位弹道、高台可直接压制 | 高度差判定有明确数值定义（如 2 档高度）并有自动化弹道测试用例 |

## 4. 非功能需求（Non-Functional Requirements）

| 编号 | 类别 | 需求描述 | 验收标准 |
| --- | --- | --- | --- |
| NFR-101 | 性能 | GTX 1660 / 1080p / 高画质稳定运行 | ≥ 60 FPS；战斗场景波动 ≤ 10%；DrawCall ≤ 300；单场景三角面 ≤ 150 万 |
| NFR-102 | 响应 | 加载与重开速度 | 点击开始 → 进入首房 ≤ 3s；死亡结算"再来一局" → 进入新局战斗 ≤ 5s（均异步加载，带进度反馈） |
| NFR-103 | 手感 | 输入延迟 | 点击 → 子弹出膛 ≤ 100ms；移动/翻滚输入响应 ≤ 1 帧 |
| NFR-104 | 稳定性 | 崩溃与存档安全 | 每日构建自动跑 20 整局，崩溃 = 0；存档损坏率 < 0.1%（FR-902 保障） |
| NFR-105 | 兼容性 | Windows 10/11 64 位 | 最低：i5-8400 / GTX 1060 / 8GB / 1080p（低画质 30 FPS 可玩）；推荐：i5-12400 / RTX 3060 / 16GB（高画质 60 FPS） |
| NFR-106 | 安全与隐私 | 纯单机零采集 | 全程无网络请求（可用抓包断言）；无账号；崩溃日志仅本地 |
| NFR-107 | 可维护性 | 代码与配置质量 | 核心逻辑（伤害/Buff/掉落/PCG）单测覆盖 ≥ 70%；内容新增零代码改动（纯配置表）；遵守团队 C# 编码规范 |
| NFR-108 | 易用性 | 操作适配 | 全键位可重映射；色盲友好弹幕配色与字幕选项预留（P2 实现，架构 P1 预留） |
| NFR-109 | 本地化 | 多语言预留 | 全部文本走集中文本表，禁止硬编码字符串；v1.0 仅中文，架构支持后续增语种 |
